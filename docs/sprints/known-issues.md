## PQ-1 앱 화면 기준 "로그인 후 배경 제거 + 옷장 저장"

| 항목 | 내용 |
|---|---|
| 현재 상태 | **서비스 단계는 검증됨 / 앱 화면 연결은 미검증** |
| 검증된 것 | QA Supabase 프로젝트에서 실제 로그인 토큰 → 백엔드 인증 → 실제 SlimSAM 배경 제거 → Storage 업로드 → `clothes` 저장 → 재로그인 후 재조회(E2E-01·03·05·06, 커밋 `1172784`). 앱의 `saveClothingToSupabase`와 같은 순서를 Node에서 재현한 것 |
| 미검증인 것 | 앱이 실제로 세션 토큰을 붙여 보내는지(`src/lib/api.ts`), 분석 화면 → 회원가입·로그인 → 옷장 이동까지 화면이 이어지는지, 옷장에 배경 제거 이미지가 표시되는지 |
| 자동화하지 못한 이유 | 원격 Supabase로 전송되는 비밀번호를 브라우저에 입력하는 것은 Claude의 브라우저 안전 규칙상 불가. iOS 시뮬레이터는 탭·입력 도구가 없음 |
| 위험 | 토큰 첨부가 빠지면 오류 없이 원본 사진으로 저장된다(이미지 처리 실패 → 원본 대체). 화면에서는 "저장 성공"으로 보이므로 반드시 이미지로 확인해야 한다 |
| 확인 방법 | iOS 시뮬레이터: 로그아웃 → 사진 선택 → 분석 → "내 옷장에 저장" → 로그인 → 옷장에서 **배경이 제거된 이미지**인지 확인(흰 옷 + 흰 배경 사진은 KI-1 때문에 제외). 백엔드 로그에 `/segment-garment-local` 200이 남는지 확인 |
| 닫는 조건 | 위 확인 통과 + 백엔드 로그 확인 |

## KI-1 배경 제거 "성공" 응답인데 결과가 잘못됨 — 이미지 품질 평가 필요

| 항목 | 내용 |
|---|---|
| 증상 | 흰 셔츠 사진에서 `/segment-garment-local`이 **200(성공)** 을 반환했지만 결과는 14×16 픽셀(단추 하나)이었다. 셔츠는 사라지고 단추만 남는다. 앱은 성공으로 보고 BRIA 대체 경로로 넘어가지 않으므로 이 조각이 옷장 이미지로 저장된다 |
| 원인 | 서버가 SlimSAM에 Gemini box와 함께 옷 중심점(세로 55% 지점)을 양성 점으로 보낸다. 그 점이 단추 위에 놓이면 SAM의 IoU가 가장 높은 마스크(0.95)가 단추가 된다. 같은 이미지에 box만 주면 셔츠 전체(이미지의 57%)가 잡힌다 |
| 재현 | `npm run test:e2e`의 E2E-09(todo). 저장소 상품 이미지 4장 중 1장 재현(스니커즈·로퍼·데님 정상) |
| 핵심 교훈 | **API 성공(HTTP 200)은 분리 품질을 보장하지 않는다.** 배경 제거 결과는 응답 코드가 아니라 결과 이미지 자체로 평가해야 한다 |
| 필요한 품질 평가 | ① **서버 측 품질 게이트:** 마스크(또는 결과 이미지)가 Gemini box 면적의 기준 비율(초안 25%) 미만이거나, 투명 비율이 극단적(5% 미만·95% 초과)이면 "저품질"로 응답 → 앱이 BRIA로 대체 ② **품질 기록:** 처리 경로(sam/bria/original)와 품질 지표(box 대비 면적, 투명 비율)를 로그·이벤트로 남겨 실제 비율을 측정(PRD NFR-08, FR-UPL-01 ⑤) ③ **평가 세트:** 다양한 옷·배경(흰 옷+흰 배경, 착용샷, 패턴, 작은 액세서리) 이미지로 경로별 성공률을 정기 측정(AUDIT V-7) |
| 영향 | 일부 사용자 옷이 단추·로고 조각 이미지로 저장됨. 옷장 신뢰도 하락. PRD FR-UPL-03, NFR-08 |
| 처리 계획 | Sprint 1A-3 첫 작업(인증·보안 주제인 1A-2와 분리. 품질 평가 세트·BRIA 비용 판단 필요) |
| 닫는 조건 | E2E-09가 일반 테스트로 통과(흰 셔츠가 셔츠로 분리되거나, 저품질로 판정되어 BRIA로 대체), 품질 지표 기록 |

## KI-2 PRD SEC-01 응답 코드와 구현 차이

| 항목 | 내용 |
|---|---|
| PRD | SEC-01 AC ① 토큰 없는 요청은 5개 엔드포인트 모두 401 ② 익명 토큰은 `/analyze-clothing`만 허용, 이미지 처리 엔드포인트는 **403** |
| 구현(Sprint 1A-1) | ① `/analyze-clothing`은 토큰 없는 요청도 허용(guest, IP당 시간당 10회, 임시) ② 익명 토큰의 이미지 처리 요청은 **401 `AUTH_REQUIRED`** |
| 이유 | 운영 Supabase의 익명 로그인이 꺼져 있어 로그인 전 분석을 유지하려면 임시 guest 허용이 필요했다 |
| 처리 계획 | Sprint 1A-2 S2-05: 익명 토큰의 이미지 처리 거절을 403 `ANONYMOUS_NOT_ALLOWED`로 맞춘다. 토큰 없는 분석은 로그인 전 분석 보호를 위해 `ALLOW_TOKENLESS_GUEST` 플래그로 남기고, 끄는 시점은 PO 결정(1A-2 계획 D3) |
| 닫는 조건 | AC-G3 ①~③ 자동 테스트 + QA E2E 통과 |
