## 1. 원칙

- **판단 기준을 프롬프트에 넣는 것만으로 정확도가 오른다고 보지 않는다.** 같은 사진, 같은 모델 설정에서 넣은 팔과 넣지 않은 팔을 짝으로 비교해 확인한다.
- **값과 문장은 Lab 내보내기에서만 온다.**
  - 프롬프트는 확정 번들(공동창업자 서명 후)에서 빌드할 때 만든다.
  - `prompt_sha`·`schema_sha`·사전 버전을 결과에 남긴다.
  - 앱 코드에 정의 문장을 직접 쓰지 않는다.
- **Lab 원문(한국어)을 그대로 넣는다.** 번역하면 원문과 달라질 수 있고, 어떤 문장이 영향을 줬는지 추적하기 어려워진다.
  - 영어 틀 + 한국어 기준 문장 조합으로 시작한다.
  - 번역본은 필요하면 별도 팔로 비교한다.

## 2. 전체 제공 vs 선택 제공

실제 사전(실루엣 r1 17개, 핏은 Lab 백업 7개 중 사진으로 판단 가능한 6개)으로 만든 프롬프트 크기:

| 팔 | 내용 | 문자 수 | 한글 | 스키마 |
|---|---|---|---|---|
| A0 | 운영 프롬프트 그대로 | 1,624 | 0 | 운영(실루엣 없음, 핏 6 앱 값) |
| A1 | A0 + 미확정 규칙 | 2,258 | 0 | 새 스키마(핏 6 + undetermined, 실루엣 17 + undetermined + not_applicable, 2순위) |
| A2 | A1 + 묶음별 후보 + 값마다 정의·제외·판단 원칙(예시·포함 문장 뺌) | 8,705 | 3,418 | A1과 같음 |
| A3 | A1 + 모든 값의 정의·포함·제외·판단 원칙·예시 | 10,416 | 4,808 | A1과 같음 |
| 2단계(참고) | 1차 호출로 대분류를 안 뒤, 2차에 그 묶음 값만 전체 기준 | 2차 블록 2,196(셔츠)~3,658(원피스) | — | 호출 2회 |

- **한 번 호출하는 구조에서는 '대분류에 맞는 기준만'을 줄 수 없다.** 호출하기 전에는 대분류를 모르기 때문이다.
  - A2는 기준을 묶음별로 정리해 고를 범위를 좁히는 방식이다. 그래서 A3 대비 약 16%만 줄어든다.
  - 실제로 범위만 주려면 2단계 호출이 필요하고, 그러면 호출 수와 지연이 두 배가 된다.
- 토큰 수는 문자 수로 추정하지 않는다. 파일럿 실호출에서 `usageMetadata`로 실제 값을 잰다(이미지 토큰 포함).

| 방식 | 장점 | 단점 |
|---|---|---|
| 전체 제공(A3) | 모든 경계를 한 번에 봄. 대분류를 잘못 골라도 기준이 있음 | 가장 김. 관련 없는 기준이 주의를 흐릴 수 있음 |
| 묶음 정리(A2, **1차 권장**) | 호출 1회 유지. 묶음별 후보를 먼저 보게 함 | 크기 절감이 작음 |
| 2단계 | 범위가 정확하고 2차 기준이 짧음 | 비용·지연 2배. 1차 대분류 오류가 2차로 이어짐 |

- **권장:** A1·A2·A3를 같은 사진으로 비교하고, 2단계는 A2·A3가 A1보다 낫지 않을 때만 시험한다.
- 비교 대상 필드에 핏·실루엣 외의 기준도 넣을 수 있다. 예: 세부분류 경계(베스트 3종, 점프수트·롬퍼). 사전 로더는 속성을 가리지 않는다.

## 3. 포함·제외 기준을 실제로 쓰게 하는 방법

1. **제외 기준 먼저:** 프롬프트에 "값을 고르기 전에 제외 기준을 적용하라"고 적고, 문장마다 키를 함께 둔다(`제외: … flared로 구분`).
2. **우선순위를 명시:** 두 값이 동시에 맞을 때의 규칙을 따로 적는다. mermaid > flared, jogger > tapered, boxy > rectangular, 원피스에서 상체 폭 + 허리 수축이면 X.
3. **2순위를 받는다(평가에서만):** `silhouette_runner_up`.
   - 경계 쌍에서 1·2순위가 정답 쌍과 맞는지 보면, 모델이 경계를 인식하는지 알 수 있다.
   - 운영에서는 받지 않는다(토큰 절약).
4. **모델이 스스로 말한 이유는 근거로 쓰지 않는다.** 대신 결과로 확인한다. 300벌 구성안 4.2의 혼동 쌍마다 A1 대비 A2·A3의 혼동률이 줄었는지 본다.
   - 예: X↔flared, wide↔jogger, boxy↔rectangular, barrel↔balloon.
5. **기준 문장 자체의 결함을 먼저 고친다.** 사전 로더가 경계가 한쪽에만 적힌 쌍을 찾는다.
   - r1: 15쌍. r2 초안 수정안을 적용하면 12쌍이 남는다.
   - 수정안 때문에 새로 생긴 단방향 경계도 2쌍 있다: wide→jogger, tapered→balloon.
   - 한쪽에만 적힌 경계는 모델이 반대 방향에서 놓치기 쉽다. Claude C 회신에 목록을 넣었다.

## 4. 사진으로 판단할 수 없는 값

| 속성 | 사진 판단 | 처리 |
|---|---|---|
| 대분류·세부분류·주색상·실루엣 | 가능 | 값. 실루엣은 신발·가방·액세서리면 not_applicable |
| 핏 | **착용 사진이 있어야 함** | 제품 단독 사진에서 여유량이 보이지 않으면 `undetermined` |
| 핏 compression | 불가(Lab: "타이트하게 보인다는 이유만으로 분류하지 않음") | **사진 분석 enum에서 뺀다.** 상품 설명 같은 텍스트 근거가 있을 때만 사람이 기록 |
| 소재(섬유) | 일부 | 1라운드는 운영 그대로(필수, other 포함). 평가에서는 정답에 '판단 불가'를 표시해 추측 비율을 잰다 |
| 조직·편성, 후처리·가공, 두께감 | 텍스트·확대 사진 필요 | Gemini에 묻지 않는다(앱 필드 없음, 연구 전용) |

- 스키마에 `undetermined`를 enum 값으로 둔다. Gemini 구조화 출력은 enum 밖 값을 낼 수 없으므로, 미확정을 고를 수 있는 값이 있어야 추측하지 않을 수 있다.
- 지금 운영 스키마(A0)는 미확정을 낼 수 없다. 그래서 판단 불가 의류에서 추측 비율이 100%로 나온다. 합성 파일럿에서도 그대로 확인됐다(A0 핏 추측 2/2, 신발에도 fit을 냄).
- 정답 라벨러는 사진만 보고 판단할 수 없는 칸을 `undeterminable`로 표시한다. 그래야 '정직한 미확정'과 '추측'을 구분해 셀 수 있다.

## 5. 평가 구조

### 5.1 정답 데이터 (의류 1벌 = 1행)

- 키: 계약 이름(category, subcategory, main_color, fit, silhouette)과 Lab 키를 쓴다.
- `<필드>_status`: assessed · undeterminable · not_applicable
- `<필드>_app`: 앱 enum에 없는 Lab 값의 변환값. 예: Lab 대분류 jumpsuit → 앱 dress. 계약 app_value에서 채운다.
- `acceptable`: 경계 사례에서 함께 인정할 값(`silhouette:flared`). **엄격 정확도에는 넣지 않고 따로 보고한다.**
- `shot_type`(product·worn), `boundary_set`(300벌 구성안 4장), `labeler`
- **사람 2명이 독립 라벨링한다.** 일치도(코헨 카파)가 모델 정확도의 상한선이다.
  - 불일치 의류는 공동창업자가 정답을 정하고, `disagreement` 표시를 남긴다.
  - Lab의 `disagreement_reviews`와 형식을 맞춘다.

### 5.2 필드마다 따로 판정

| 판정 | 뜻 | 정확도 분모 |
|---|---|---|
| correct | 정답과 같음 | 포함 |
| acceptable | 경계 대안과 같음 | 포함(엄격에서는 오답으로 셈) |
| wrong | 다름 | 포함 |
| abstain_miss | 정답이 있는데 미확정 | 포함 |
| invalid | 스키마 밖·형식 오류·응답 없음 | 포함 |
| abstain_ok | 판단 불가 → 미확정 | 제외(추측 비율로 보고) |
| guess | 판단 불가인데 값을 냄 | 제외(추측 비율로 보고) |
| unsupported | 정답 값을 이 팔의 enum으로 표현할 수 없음(예: A0에서 fitted) | 제외(개수 보고) |
| na_ok / na_violation | 해당 없는 대분류에서 값을 내지 않음 / 냄 | 제외(위반율 보고) |

- 지표(필드마다):
  - 엄격 정확도(윌슨 95% 구간), 경계 대안 포함 정확도
  - 답한 것 중 정확도, 답한 비율, 추측 비율, 해당 없음 위반율, 미지원 개수
  - 클래스별 재현율 평균, 혼동 행렬
- 부분집합: 경계 세트, 착용 사진, 제품 사진, 대분류별
- 계층: 대분류가 맞은 의류만으로 낸 세부분류 정확도. 대분류 오류가 세부분류 점수에 섞이지 않게 한다.

### 5.3 표본 크기로 알 수 있는 것

- 엄격 정확도 95% 구간의 반폭:
  - 300벌, 정확도 70%: ±5.2%p
  - 100벌: ±8.8%p
- **핏은 착용 사진만 채점되므로 실제 n이 줄어든다.** 구성안이 착용 40%이면 약 120벌이고, 반폭은 ±8%p 안팎이다.
- 짝 비교(McNemar)는 두 팔의 답이 갈린 의류 수에 따라 달라진다.
  - 300벌에서 갈린 의류가 45벌이면 5%p 차이도 p ≈ 0.036이다.
  - 75벌이면 5%p 차이는 p ≈ 0.105로 확인되지 않고, 8%p 이상이어야 확인된다.
- 세부분류 클래스별 정확도는 클래스당 4~16벌이라 참고용으로만 본다.

  - 이미지 라이선스: 300벌 이미지를 Google API로 보내도 되는지(Lab 라이선스 체크리스트)
  - 무료 등급 사용 시 Gemini 약관상 입력이 제품 개선에 쓰일 수 있다는 점
  - 착용 사진의 얼굴 비식별

## 8. Knowledge Lab 최종 자료가 필요한 부분

- 실루엣 판단 기준 최종 문장(r2 수정안 9건 반영 여부)
- **핏 인계 문서**(지금 없음):
  - regular·relaxed·oversized 판단 기준이 포함·제외 형식이 아니다
  - regular와 relaxed의 판단 기준 문장이 같다
- 대분류별 적용 범위, A의 범위(전체 vs 하단)
- 확정 번들(서명 후). 프롬프트는 확정 값만으로 만든다
- 300벌 정답 라벨(두 명)과 경계 세트 표시
