## 1. 목표와 원칙

**최우선 목표:** 프리미엄 구독(STYLESEED PLUS, B2C)과 커머스 제휴 수수료(B2B2C), 두 수익모델의 **초기 사업화 가능성**을 실제 사용자·실제 파트너 데이터로 확인한다. 기능 수를 늘리거나 정식 스토어 출시를 하는 것이 목표가 아니다.

사업계획서의 단계(추천 품질 → 실제 상품 연동 → 수익모델 → PMF)는 유지한다. 다만 추천엔진 전체 고도화를 기다리지 않고, **수익모델 실험에 필요한 최소 추천 품질**만 확보한다.

| # | 원칙 |
|---|---|
| P1 | **행동 단계를 섞지 않는다.** 클릭 · 공식몰 이동 · 구독 의향 · 실제 구매 · 실제 매출은 서로 다른 지표다(2장). 아래 단계 값을 위 단계 성과로 보고하지 않는다 |
| P2 | **가짜 결제를 만들지 않는다.** 연구용 Paywall은 결제 수단 입력·결제 완료 표시·구독 상태 변경이 없다. "구독 완료"·"결제 완료" 같은 문구를 쓰지 않는다 |
| P3 | **실험 이벤트와 실제 거래 이벤트를 분리한다.** 실험 이벤트는 연구 전용 저장소에만 쓰고, Phase 5의 실제 구독·결제 이벤트(`subscription_started` 등)와 이름·저장소를 공유하지 않는다 |
| P4 | **작은 표본은 탐색으로만 해석한다.** 18명 가격 실험, 15~20명 사용성 검증은 방향 신호다. "최적 가격 확정", "전환율 N%"로 보고하지 않는다 |
| P5 | **있는 것을 먼저 쓴다.** 분석(`/analyze-clothing`), 코디 점수(`getRankedLooksForItem`, `evaluateOutfit`), Missing Item(`getMissingItemSuggestion`), Shop 매칭, 사진 AI 동의(Claude B `aiConsent`)를 재사용한다 |
| P6 | **기존 품질·보안 테스트를 유지한다.** `test:engine`(엔진 스냅샷), `test:client`, `test:backend`, `test:quality`, `test:fkd`, QA E2E가 모든 변경 후 통과해야 한다 |
| P7 | **다른 트랙의 영역을 고치지 않는다.** 출시·인프라·스토어·계정 삭제·처리방침은 Claude B, Knowledge Lab은 Claude C. 필요한 변경은 핸드오프 문서로 요청한다 |
| P8 | **별도 승인:** 운영 DB 변경, 유료 API 전환, Git Push, 외부 배포 |

## 2. 행동·수익 지표 사다리 (엄격 구분)

| 단계 | 정의 | 1라운드 수집 | 증거 수준 |
|---|---|---|---|
| L1 상품 노출 | 추천 상품 카드가 화면에 보임 | 앱 이벤트 | 관심 |
| L2 상품 클릭 | 상품 카드를 눌러 상세를 엶 | 앱 이벤트 | 관심 |
| L3 공식몰 이동 | 공식몰 링크를 열었음(앱이 외부 브라우저 열기에 성공) | 앱 이벤트 | 구매 여정 진입 |
| L4 구독 의향 | 연구용 Paywall에서 "구독을 고려하겠다" 선택 | 실험 이벤트 | **의향(행동 아님)** |
| L5 실제 구매 | 브랜드가 확인한 주문(UTM 또는 쿠폰 코드 기준) | **브랜드 보고만**(앱이 알 수 없음) | 행동 |
| L6 실제 매출 | 정산된 제휴 수수료 또는 실제 구독 결제 | 계약·정산 서류만 | 매출 |

- 1라운드에는 인앱 결제가 없으므로 **L6 구독 매출은 0**이다. 제휴 수수료는 계약이 있고 정산이 일어난 경우에만 L6로 적는다.
- L3 공식몰 이동은 모든 브랜드에서 앱 이벤트로 기록한다. UTM은 브랜드가 허용한 경우에만 붙인다(D4).
- L5는 브랜드가 UTM·쿠폰 기준 주문을 알려 주기로 동의한 경우에만 수집한다. 동의가 없으면 "측정 안 됨"으로 적는다(0으로 적지 않는다).

## 5. 최소 추천 품질 (G7)

추천엔진 고도화(Phase 1B-2·1B-3)는 2라운드로 넘긴다. 1라운드에는 **실험에서 사용자에게 보이는 추천**만 검증한다.

| 검증 대상 | 방법 | 최소 기준(제안, 공동창업자 확정) |
|---|---|---|
| 평가 기준 자체 | Pilot 20 코디를 두 사람이 독립 평가 → 차원별 1점 이내 비율, 종합 순위 상관 | 종합 점수 1점 이내 일치 70% 이상. 미달이면 기준 문장(D-F05) 보완 후 진행 |
| PLUS 결과에 보이는 코디 | 실험용 구매 예정 옷 샘플(공동창업자가 고른 10벌 × 샘플 옷장) → 엔진 B 상위 3개 코디를 두 사람이 평가 | 상위 3개 중 두 사람 모두 1~2점("부적합")을 준 코디 **20% 이하** |
| Missing Item → 상품 매칭 | 실험 상품 10~30개가 실제로 추천되는 경우를 모아 "이 옷장에 맞는 상품인가" 1~5점 | 평균 3점 이상, 1~2점 상품은 실험 목록에서 제외 |
| 확장(선택) | 60개 세트 + 기존 엔진 기준선 | 1라운드 필수 아님. 공동창업자 시간이 남으면 진행 |

공동창업자에게 1라운드에 필요한 패션 결정은 **D-F05(1~5점 기준 문장), D-F08(평가 차원), D-F10(Pilot 코디)**뿐이다. 규칙 작성용 결정(D-F01~04·06·07·09)은 2라운드로 미룬다.
