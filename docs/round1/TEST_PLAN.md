# Round 1 테스트 설계

- 작성: 2026-10-19 (Claude A, R1-01) · 범위: R1-01 도구(완료) + R1-02 구현 예정 기능(설계)
- 원칙: 기존 품질·보안 테스트는 그대로 유지하고 **모든 변경 후 전부 통과**해야 한다. 실험 이벤트는 QA 프로젝트에서만 검증한다(D1). 운영 DB에 쓰는 테스트는 별도 승인 전까지 없다

## 3. R1-02 기능 테스트 설계

### 3.1 연구 모드·이벤트 (상세 시나리오: `PLUS_PRICING_EXPERIMENT.md` 10장 TS-P01~P24)

| 수준 | 대상 | 방법 |
|---|---|---|
| 단위 | 코드 입력 검사, 배정(앱이 `assignment-r1-plus-price-v1.json`을 그대로 읽는지, 해시 비교), 이벤트 생성(필수 필드), 대기열·재전송, 1회·선택 규칙 | `node --test` + 가짜 저장소 |
| 계약 | 앱이 만든 이벤트가 `scripts/round1/events.mjs`의 `validateEvent`를 오류 0으로 통과 | 앱 이벤트 생성 함수를 순수 함수로 두고 같은 테스트에서 검사 |
| QA E2E | (DB 방식) `research_events` 삽입·중복 ID·교차 계정 조회 0건·익명 거부·코드 재사용 거부·계정 삭제 연쇄 | QA 프로젝트, 1A-2 E2E 방식 |
| 화면 | Paywall 세 그룹 문구 동일(가격만 다름), 금지 문구 0건, 결제 고지 문구 존재 | 렌더링 문자열 비교 |
