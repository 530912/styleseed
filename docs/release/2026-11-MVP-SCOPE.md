## 1. 배포 방식 (범위를 정하는 전제)

| 방식 | 내용 | 11/09까지 가능성 | 필요한 승인·준비 |
|---|---|---|---|
| **M1 진행자 기기 + 내부 빌드 (권장)** | 진행자 휴대폰 1~2대에 EAS preview 빌드 설치(Android APK / iOS ad hoc), 백엔드는 Railway | 가능 | ⛔ Railway 배포, ⛔ EAS 빌드, iOS는 Apple Developer 계정(⛔ 결제). Android만 쓰면 Play 계정 없이 APK 설치 가능 |
| **M2 진행자 기기 + Expo Go (대안)** | 진행자 PC에서 백엔드·Metro 실행, 같은 Wi-Fi, 휴대폰 Expo Go로 실행 | **바로 가능**(F-55) | 없음(지금 개발 환경 그대로). 단점: 세션 장소 네트워크 의존, 앱 이름·아이콘이 Expo Go, 개발 모드 성능 |
| M3 참가자 본인 기기 설치 | TestFlight 외부 테스트 / Play 비공개 테스트 | **어려움** — 스토어 계정 미등록, 처리방침 URL 없음, 베타 심사·(개인 계정이면) 12명×14일 규칙 | 스토어 계정·처리방침 게시·심사 |

## 3. B — 있으면 좋지만 첫 조사에서 빼도 되는 기능

| 기능 | 현재 | 빼도 되는 이유 |
|---|---|---|
| 카메라 촬영 | 없음 | 휴대폰 카메라로 찍은 뒤 앨범에서 고르면 된다(진행자 안내) |
| 날씨 기반 Today's Look | 엔진 PASS | 홈에 있고 동작하지만 조사 핵심 질문이 아니다. 위치 권한을 거부해도 다른 기능은 쓸 수 있다 — **남겨 두되 필수 점검에서 제외** |
| 저장 후 속성 수정 | 없음 | 저장 전 분석 화면에서 수정 가능. 잘못 저장하면 삭제 후 재등록 |
| 비밀번호 재설정 | 없음 | 진행자 기기·진행자 계정 사용 |
| 온보딩 | 없음 | 진행자가 세션 도입부에서 설명 |
| 배경제거본/원본 전환, 사진 교체 | 코드 있음 | 보조 기능. 동작하면 둔다 |
| 계정 화면·앱 안 계정 삭제 | `release/beta-prep` | 진행자 기기 세션은 진행자가 세션 후 계정·데이터를 정리. **참가자 본인 기기 배포(M3) 때는 A로 올라간다** |
| PLUS(구매 전 옷장 활용도), 연구용 Paywall·가격 실험 | 없음(R1-02-05·06) | **PO 결정.** 수익모델 검증의 핵심이면 A로 올린다. 개발량 17~23h로 11/08까지 A-8·A-10과 함께 하기는 빠듯하다 |
| 추천 결과 저장·다시 보기 | 없음 | 매번 다시 계산해도 같은 결과 |

## 5. 사용자 조사 최소 기능 범위 (한 줄)

**가입/로그인 → 사진 AI 동의 → 앨범 사진 → AI 분석·수정 → 옷장 저장 → 옷장 보기 → 이 옷으로 코디(점수·TOP 3) → Missing Item → 상품(실제 또는 "예시"로 표시) → (가능하면) 공식몰 이동**, 그리고 이 흐름의 최소 이벤트 기록.
