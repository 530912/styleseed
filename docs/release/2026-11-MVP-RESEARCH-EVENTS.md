## 4. 추천 코디 저장 여부 — 결정 필요

앱에 코디 저장 기능이 없어 앱 기록으로는 잴 수 없다. 이번 범위(새 기능 개발 지양)에서는 **인터뷰 질문으로 대체**를 권장한다: Styling 화면을 본 직후 "이 코디를 나중에 다시 보려고 저장하고 싶으세요?"(예/아니오 + 이유). 앱으로 재야 한다면 [이 코디 저장] 버튼 + `outfit_saved` 이벤트(기기 저장만, 약 3~4시간)가 필요 — **PO 결정**.

## 5. 진행자 운영 순서 (세션마다)

1. 홈 화면 **STYLESEED 로고를 길게 누름** → 진행자 화면.
   - 참가 코드가 없으면 홈에 빨간 안내 문구가 보인다.
2. 참가 코드 입력 → [본 조사 시작] (팀 연습은 `R1-T01~T03` + [리허설 시작] → 분석에서 자동 제외)
3. 홈으로 → 참가자에게 기기 전달
4. 세션 후 진행자 화면 → **[기록 내보내기]** → 공유 시트로 진행자 PC(에어드롭·메일·메모)로 보냄 → 파일 받았는지 확인
5. [세션 종료] 두 번 → 세션 닫힘 + **로그아웃 + 기기 옷장 캐시 삭제**
6. PC에 받은 것을 확인한 뒤에만 [이 기기 기록 삭제]

**통합 후 추가 1단계:** AI 동의가 기기 단위로 저장되므로(B 구현), 세션 종료 때 동의도 초기화해야 다음 참가자가 동의 화면을 본다 → 통합 브랜치에서 `withdrawAiConsent()`를 세션 종료에 연결(A, 인계 문서 참고).

## 6. 분석

```
node scripts/round1/events.mjs <받은파일.jsonl> --out data/round1/reports/<날짜>
```
- 중복 이벤트 ID 제거, 형식 오류·리허설·개발 환경 제외 후 집계.
- 새로 추가된 결과: `r1_core_participants.csv`(참가자별), 요약의 **핵심 흐름** 표 — 등록 완료율, 등록 실패, AI 분석 실패율·시간 중앙값, **AI 결과 수정률과 고친 속성**, Missing Item 클릭률, 예시 상품 보기율.
- 여러 기기·세션 파일은 한 파일로 이어 붙여 넣으면 된다(JSON Lines).
