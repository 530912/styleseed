## 4. 웹 호스팅

`expo export --platform web`(정적 출력)은 **화면마다 HTML 파일 + 해시가 붙은 JS**를 만든다 → 서버 기능이 필요 없는 정적 호스팅이면 된다. 주소 `/closet` → `closet.html` 연결(clean URL)이 필요하다.

| 후보 | 비용 | 조건·한계 | 판단 |
|---|---|---|---|
| **Cloudflare Pages** | **무료** | 정적 파일 대역폭 무제한(2차 자료), 월 500회 빌드, 파일 2만 개. 상업적 사용 금지 조항 확인 안 됨(약관 직접 확인 필요). `wrangler pages deploy`로 **git 연결 없이 폴더만 올릴 수 있음** | **권장** |
| B의 카페24 서버(Caddy)에 같이 올리기 | 추가 0원 | 서버 하나로 API·웹 모두 → 장애 시 같이 멈춤, 서버 배포 절차에 웹이 묶임 | 대안 |
| Netlify 무료 | 무료 | 월 크레딧 소진 시 사이트 전체 정지, 배포당 크레딧 사용 | 비권장 |

| GitHub Pages | 무료 | 공개 저장소·Push 필요, 사업용 금지 | 제외 |

## 9. 10/27 2차: 크래시 원인·회귀 시험·재검증

**크래시 원인:** Playwright WebKit(build v2215) 결함.
- 앱 화면을 지워도(`body` 비움), 저장소를 비워도, 타이머를 모두 취소해도 크래시가 났다.
- **같은 출처**로 이동하면 크래시가 났고, **다른 출처**로 이동하면 정상이었다 → 이전 페이지를 정리하는 단계의 문제다.
- 앱 코드가 없는 **빈 HTML**에서 `pushState` 2번 → 뒤로 → 새로고침만 해도 데스크톱·모바일 설정 모두 크래시.
- **실제 iOS 26.5 Safari(시뮬레이터)**: 빈 HTML 5/5 정상. **앱의 같은 경로(옷장 → 옷 탭 → 코디 → TOP 3 → 뒤로 → 새로고침)도 5/5 정상**이다. 같은 시험 드라이버를 Playwright에서 돌리면 크래시가 났다.
- → **앱은 고치지 않는다**(우회 코드는 회귀 위험만 늘림). 이 경로는 실제 Safari 회귀 시험으로 확인한다.

**회귀 시험:** `bash scripts/webqa/run-safari-sim.sh [횟수]`. 가짜 Supabase + 시험 빌드 복사본 + 시뮬레이터 Safari에서 실행한다. 10/27 결과:

| 항목 | 결과 |
|---|---|
| A. 코디 → TOP 3 → 뒤로 → 새로고침 | 5/5 생존 |
| B-1. 24MP(5712×4284) | → 1600×1200 JPEG 103KB |

**정정(WF-1):** iOS 26.5 시뮬레이터 Safari에서는 예전 방식(원본 크기 canvas 24.5M 픽셀)도 그려졌다. canvas 상한(16.7M 픽셀)은 이 환경에서 **재현되지 않았다**. 외부 자료는 상한이 기기 메모리에 따라 다르다고 한다. 그래서 수정은 **메모리 절약** 목적으로 유지한다(원본 canvas 약 98MB → 1600px 약 10MB). 실제 iPhone 확인이 필요하다.

**Gemini 타임아웃:**
- 앱은 50초, 서버 시간 초과 처리 시험(TS-10, 504 `AI_TIMEOUT`)은 통과했다.
