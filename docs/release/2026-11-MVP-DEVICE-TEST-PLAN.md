## 2. 서버 주소 설정 — 코드 수정 없이 환경변수로만

앱은 `EXPO_PUBLIC_API_URL`을 읽고, **비어 있으면 `http://localhost:3001`** 을 쓴다(`src/lib/api.ts`). 휴대폰에서 localhost는 휴대폰 자신이라 **분석이 "서버에 연결하지 못했어요"로 실패**한다. 지금 이 PC의 `.env`에는 이 값이 **없다**.

| 단계 | 설정 | 누가 |
|---|---|---|
| 지금(M2, Expo Go) | `.env`에 `EXPO_PUBLIC_API_URL=http://<PC LAN 주소>:3001` (오늘 이 PC: `172.16.1.230`, 장소·Wi-Fi가 바뀌면 바뀜 → `ipconfig getifaddr en0`) | PO(로컬 `.env`) |
| B 배포 후(M1) | EAS 환경 `preview`에 `EXPO_PUBLIC_API_URL=https://<Railway 주소>` | B |
| 연구 빌드 | EAS 환경에 `EXPO_PUBLIC_RESEARCH_MODE=true` | B |
| 조사 DB 확정 후 | `EXPO_PUBLIC_SUPABASE_URL`·`EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 조사용 프로젝트로(BUG-25) | B + PO |
| Gemini 유료 전환 후 | `EXPO_PUBLIC_GEMINI_PAID_TIER=true`(무료 등급 고지 숨김) | B |

`EXPO_PUBLIC_*` 값은 빌드 때 앱에 들어간다 → 바꾸면 **Metro 재시작(`--clear`) 또는 재빌드**가 필요하다. 서버 비밀키는 여기에 넣지 않는다.

## 5. PO가 직접 실행할 테스트 절차

### 5-0. 준비물

- 휴대폰: Android 1대(필수), iPhone 1대(있으면). 각각 Expo Go 최신(SDK 57 지원) 설치

- 테스트용 옷 사진 6장 이상: 상의 2, 하의 2, 신발 1, **옷이 아닌 사진 1**(BUG-06 확인용). iPhone에서 직접 찍은 HEIC 1장, 세로 사진 1장 포함
- 테스트 이메일 2개(실제 개인 메일 말고 팀 테스트용)
- 기록용: 이 문서 결과 칸, 화면 녹화(선택)

### 5-1. 실행 (M2, Expo Go)

터미널 2개:
```
# 1) 서버
npm run backend
# 2) 앱 (.env에 EXPO_PUBLIC_API_URL=http://<LAN 주소>:3001, 연구 모드 확인 시 EXPO_PUBLIC_RESEARCH_MODE=true)
npx expo start --clear
```
휴대폰 카메라(iOS) 또는 Expo Go(Android)로 QR 스캔.

- Mac 방화벽이 켜져 있으면 node 수신 허용 팝업에서 [허용].
- 휴대폰 브라우저로 `http://<LAN 주소>:3001` 접속 → "STYLESEED API is running"이 안 보이면 주소·Wi-Fi·방화벽 문제.

> 주의: 지금은 **운영 Supabase**를 쓴다(BUG-25). 테스트 계정·옷이 운영 DB에 들어간다. 조사 DB 분리 전에는 테스트 계정을 최소로 만들고 이메일을 기록해 둔다.
