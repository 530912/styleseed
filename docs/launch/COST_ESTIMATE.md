## 2. AI 분석 원가 (의류 1벌)

### 2.1 실측: 현재 요청 1회의 토큰·시간 [실측]

측정: 2026-10-19, 저장소 상품 이미지 6장(18~51KB, 525~736px), 로컬 백엔드 → 실제 Gemini API(무료 등급). 앱 코드는 바꾸지 않고 측정용 `fetch` 래퍼로 `usageMetadata`를 기록했다.

| 항목 | 값 |
|---|---|
| 요청 모델 | `.env` `GEMINI_MODEL=gemini-3.5-flash` (코드 기본값 `gemini-3.6-flash`) |
| **실제 응답 모델** | `modelVersion: gemini-3.6-flash` → 공식 가격표에 `gemini-3.5-flash`는 없고, 요청이 3.6으로 처리됨 |
| 추론 수준 | `thinkingLevel: minimal` (응답에 thinking 토큰 항목 없음) |
| 입력 토큰 | 1,618~1,643 (텍스트 프롬프트 554 + 이미지 1,064~1,089), **평균 1,637** |
| 출력 토큰 | 405~1,507, **평균 783** (출력의 상당 부분이 `mask` 다각형 좌표) |
| 성공 응답 시간 | 3.8~7.5초 (Gemini 응답 기준), 앱→결과 3.8~9.6초 |
| 재시도 | 서버는 500/503/504에서 최대 2회 재시도(2초, 4초 대기), 전체 25초 제한 |
| 오류 비율 | 10회 시도 중 **503(혼잡) 3회**, 429(무료 일일 한도) 2회, 성공 4회 |

**주의**
- 표본이 작다(성공 4회). 실제 휴대폰 사진(수 MB, 고해상도)은 이미지 토큰이 더 많을 수 있다 → 품질 실험(DEPLOYMENT_PLAN 3장)에서 실사진으로 다시 측정한다.
- 출력의 `mask`는 앱이 쓰지 않는다(`src/lib/clothes.ts`의 `USE_GEMINI_SEGMENTATION = false`). 응답 스키마에서 빼면 출력 토큰이 크게 줄어든다(코드 변경 필요, 승인 후).

### 2.2 모델별 1회 원가

[공식] 가격(유료 등급, Standard, 1M 토큰당) × [실측] 평균 토큰(입력 1,637 / 출력 783). "mask 제거"는 출력 250토큰 [가정].

| 모델 | 입력 $/1M | 출력 $/1M | 1회 원가 | 원화 | mask 제거 시 |
|---|---|---|---|---|---|
| `gemini-3.6-flash` (~2026-12-31) **현재** | 0.75 | 3.75 | $0.00416 | **5.8원** | $0.00217 (3.0원) |
| `gemini-3.6-flash` (2027-01-01~) | 1.50 | 7.50 | $0.00833 | **11.7원** | $0.00433 (6.1원) |
| `gemini-2.5-flash` | 0.30 | 2.50 | $0.00245 | 3.4원 | $0.00112 (1.6원) |
| `gemini-3.1-flash-lite` | 0.25 | 1.50 | $0.00158 | 2.2원 | $0.00078 (1.1원) |
| `gemini-2.5-flash-lite` | 0.10 | 0.40 | $0.00048 | **0.7원** | $0.00026 (0.4원) |

- Batch 가격은 절반 수준이지만 실시간 분석에는 쓸 수 없다.
- 2.5 계열은 같은 토큰 수를 가정했다. 2.5 계열은 이미지 토큰 계산 방식과 thinking 설정(`thinkingBudget`)이 달라 **실측 필요**.
- 오류(503·429) 응답은 출력 토큰이 없어 원가에 넣지 않았다([가정], 공식 과금 규칙 확인 필요).

### 2.3 배경 제거 원가

| 경로 | 1장 원가 | 근거 |
|---|---|---|
| 로컬 SlimSAM (1순위) | 서버 CPU 시간만 (2장 3.3) | [실측] 처리시간, 라이선스 Apache-2.0(무료) |
| BRIA API (SlimSAM 실패 시) | **$0.018** (소량 구간), 대량 구간 약 $0.0038 | [공식/2차 출처] Bria 가격표·호스팅 업체 표기. 현재 계정의 요금제는 미확인 |
| fal SAM2 | 사용 안 함 | 코드는 있으나 호출 안 됨(TR-08) |

BRIA 사용 비율은 측정값이 없다. 이 문서는 **저장 건의 15%** [가정]로 계산했다(KI-1 품질 게이트를 넣으면 BRIA 비율이 올라갈 수 있음).

## 3. 서버(백엔드) 비용

### 3.1 SlimSAM 실측 [실측]

장비: Apple M1 Pro(10코어, 16GB), Node 24, `@huggingface/transformers` 4.2, 모델 `Xenova/slimsam-77-uniform`

| 항목 | 값 |
|---|---|
| 모델 파일 크기 | 38MB (`node_modules/@huggingface/transformers/.cache`) |
| 로딩 시간(로컬 캐시) | **0.45초** (첫 다운로드 포함 시 약 13초 — Sprint 1A-1 E2E 기록) |
| 메모리 | 로딩 직후 RSS 218MB, **처리 중 최대 RSS 약 2.0GB**(프로세스 최대 2.8GB) |
| 1장 처리시간(웜) | **약 0.85초** (모델 추론 0.69~0.75초) |
| 1장 CPU 사용 | **약 3.7 CPU-초** (멀티스레드, 약 4.4코어 사용) |
| 첫 실행(웜업 전) | 0.9~2.8초 |

**클라우드 환산 [가정]:** 2 vCPU에서는 1장 약 2~3초, 1 vCPU에서는 약 4~6초. 메모리 때문에 **최소 3GB, 권장 4GB** 인스턴스가 필요하다. 측정 이미지가 작아(736px 이하) 실제 휴대폰 사진은 메모리·시간이 더 들 수 있다.

## 4. Supabase 비용

### 4.1 Free vs Pro [공식]

| 항목 | Free | Pro ($25/월) |
|---|---|---|
| 파일 저장 | 1GB | 100GB, 초과 $0.0213/GB·월 |
| 트래픽(egress) | 5GB(+캐시 5GB) | 250GB(+캐시 250GB), 초과 $0.09/GB(캐시 $0.03/GB) |
| DB 용량 | 0.5GB | 8GB, 초과 $0.125/GB·월 |
| 월 활성 사용자 | 5만 | 10만, 초과 $0.00325/명 |
| **일시정지** | **1주일 비활성 시 정지**(실제로 2026-10-17에 발생) | 정지 없음 |
| 초과 시 | 402 오류(서비스 차단) | 지출 한도 켜짐이 기본 |

→ **Beta부터 Pro가 사실상 필수**다. Free는 저장 1GB(옷 약 500벌 [가정 2MB/벌])·트래픽 5GB에서 막히고, 일시정지 위험이 있다.

### 4.2 저장·트래픽 추정 [가정]

가정: 옷 1벌 = 원본 1.5MB + 배경 제거 PNG 0.5MB = **2MB**(실측 필요: 운영 버킷의 기존 14개 파일은 테스트 이미지로 JPEG 평균 0.13MB, PNG 평균 0.30MB), 분석의 80%를 저장, 활성 사용자 1명이 매달 이미지 300MB 다운로드.

| MAU | 6개월 후 저장량 | 저장 초과비 | 월 트래픽 | 트래픽 초과비 |
|---|---|---|---|---|
| 300 | 약 21GB | $0 | 약 88GB | $0 |
| 1,000 | 약 70GB | $0 | 약 293GB | 약 **$4** |
| 3,000 | 약 211GB | 약 $2.4 | 약 879GB | 약 **$57** |

**트래픽 주의:** 앱은 옷장을 불러올 때마다 1시간짜리 서명 URL을 새로 만든다(`src/lib/clothes.ts`). URL이 바뀌면 이미지 캐시가 안 맞아 같은 사진을 다시 내려받는다. 썸네일·캐시 정책을 넣으면 트래픽을 크게 줄일 수 있다(별도 작업).
