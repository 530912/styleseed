## 1. 이전해도 그대로인 것

| 대상 | 이전 시 | 근거(코드 확인) |
|---|---|---|
| 앱 코드 | 변경 없음 | 서버 주소는 `EXPO_PUBLIC_API_URL` 하나 |
| 백엔드 코드 | 변경 없음 | 두 곳 모두 같은 `Dockerfile` 이미지 |
| Supabase 데이터(계정·옷·사진) | **이동 없음** | 백엔드는 상태를 갖지 않는다. 계정·옷·사진은 모두 Supabase(조사 프로젝트)에 있고, 서버는 환경변수로 같은 프로젝트를 가리키기만 한다 |

## 2. 앱 재배포 없이 서버 바꾸기 — 자체 도메인 필수

`EXPO_PUBLIC_API_URL`은 **빌드할 때 앱에 들어간다.** 주소가 바뀌면 앱을 다시 빌드·설치해야 한다.

| 방식 | 서버 변경 시 앱 재빌드 | 판단 |
|---|---|---|
| 카페24 기본 주소(`아이디.mycafe24.com`) | **필요**(Railway로 옮길 수 없는 주소) | 비추천 |
| Railway 기본 주소(`*.up.railway.app`) | 필요 | 비추천 |
| **자체 도메인의 하위 주소 `api.<도메인>`** | **불필요**(DNS만 바꿈) | **권장** |

- 앱에는 처음부터 `EXPO_PUBLIC_API_URL=https://api.<도메인>`.
- 11월: `api` A 레코드 → 카페24 서버 IP. Caddy가 인증서 자동 발급.
- 이전 시: Railway Custom Domain에 `api.<도메인>` 추가(Hobby 2개 허용, 공식 가격표) → Railway가 주는 CNAME으로 `api` 레코드 교체. 인증서는 Railway가 발급.
- 루트 도메인(`<도메인>`)이 아니라 **하위 주소**를 써야 CNAME으로 바꿀 수 있다.
- 도메인은 국내 등록처(카페24·가비아 등)에서 구입. DNS에서 **A·CNAME 레코드와 TTL 수정**이 되는지 확인.

## 3. 카페24 서버에 사용자 데이터를 남기지 않기

| 항목 | 현재 | 판단 |
|---|---|---|
| 사진 원본 | 분석 사진은 메모리에서 Gemini로 전달 후 버림. 배경 제거는 Supabase 서명 URL(10분)로 받아 메모리에서 처리 후 응답 | **디스크 저장 없음**(백엔드 코드에 파일 쓰기 0건) |
| 계정·옷 데이터 | Supabase에만 | 서버에 없음 |
| 로그 | Docker 로그(20MB × 10개 순환): 상태 코드·경로·오류 코드·분석 속성(종류·색 등)·Gemini 토큰 수. **이메일·토큰·이미지 없음**, 계정 삭제 로그는 축약 ID | 개인 식별 정보 없음. 예외: 외부 오류 객체에 **서명 URL(10분 만료)**이 섞일 수 있음 — 낮은 위험, 서버 삭제 시 함께 삭제 |
| 비밀값 | `api.env`(권한 600) | 종료 시 서버와 함께 삭제. 이전 후 **Gemini·Supabase Secret·OPS 토큰 교체 권장** |
| 서버 위치 | 일본(상품 FAQ) | 사진이 서버 메모리를 거침 → 처리방침·동의 문구의 국외 이전 항목에 추가(출시 트랙) |

## 4. 1개월 이용 후 종료·전환 절차

카페24 규정: 만료 시 서버 차단, **만료 7일 후 계정·데이터 삭제(복구 불가)**. → **만료 3일 전까지 전환 완료.**

| 시점 | 할 일 | 담당 |
|---|---|---|
| 결제 시 | **자동연장 끔**, 만료일 기록 | PO |
| 만료 7일 전 | Railway 가입·결제(자부담), 서비스 생성(`GO-LIVE-STEPS` 1장), 변수 입력 → Railway 기본 주소로 `smoke` | PO → B |
| 만료 5일 전 | DNS TTL을 300초로 낮춤 | PO/B |
| 만료 4일 전 | **로그 백업**(조사 운영 집계용): `docker compose logs --no-color api > api-final.log` → 이 PC로 복사. 사용자 데이터는 서버에 없어 백업 불필요 | B |
| 전환 | Railway Custom Domain 추가 → `api` 레코드를 CNAME으로 교체 → `/healthz`가 Railway `bootId`로 바뀌는지, `smoke` 통과 | B |
| 전환 +1일 | 카페24 쪽 요청 0 확인(`docker compose logs --since 24h`) → `docker compose down -v` | B |
| 만료일 | 연장하지 않음 → 차단·7일 후 자동 삭제. 비밀값 교체 | PO/B |

앱 재빌드·Supabase 작업·데이터 이전 없음. 실패 시 DNS를 카페24 IP로 되돌리면 복구(만료 전까지).
