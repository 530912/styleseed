## 판단

1. **서버·SSH 서비스·네트워크 개통은 정상**이다(해외 7곳에서 22번 연결).
2. **PO Mac이 있는 네트워크(221.140.166.4)가 바깥으로 나가는 22번을 막는다.** 같은 PC에서 GitHub 22번도 시간 초과였다(10/27). 기관·건물 네트워크에서 흔한 정책.
3. **80·443은 서버 쪽에서 막혀 있다**(해외에서도 시간 초과). 카페24 방화벽은 꺼져 있으므로, 신청 시 선택한 **"보안설정: 사용"이 서버 안에 22번만 허용하는 방화벽을 넣었을 가능성**이 높다(추정). 웹 서버도 아직 없다. → SSH 접속 후 서버 안 방화벽을 확인하고 80·443을 연다(`setup-ubuntu.sh`가 ufw로 허용, 기존 규칙과 충돌 여부는 접속 후 확인).

## 해결 순서

1. **휴대폰 핫스팟(또는 22번이 열린 다른 네트워크)**에 Mac을 연결 → `bash deploy/vm/preflight.sh 172.104.120.148` 다시 실행 → 22번 "연결됨"이면 같은 네트워크에서 `bootstrap.sh`.
2. bootstrap 전 B가 서버 안 방화벽 상태를 **읽기만** 해서 확인(`iptables -S`, `ufw status`, `nft list ruleset`) → 80·443 허용 방법 확정 → 실행 내용 보고 후 bootstrap.
3. 이후 배포도 SSH가 필요하므로, 평소 네트워크에서 쓰려면 둘 중 하나:
   - 기관 네트워크 담당자에게 `172.104.120.148:22` 외부 접속 허용 요청
   - 서버 SSH를 추가 포트(예: 2222)에서도 받도록 설정 — 그 포트도 막혀 있으면 효과 없음(핫스팟에서 `nc -z -G 5 portquiz.net 2222`로 먼저 확인 가능)
