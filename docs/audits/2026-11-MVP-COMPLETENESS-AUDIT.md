## ① 전체 완성도 종합 평가

| 관점 | 평가 |
|---|---|
| **구현 수준** | 핵심 흐름은 **코드로 끝까지 연결돼 있다**: 가입 → 사진 → 분석 → 수정 → 저장 → 옷장 → 코디 → TOP 3 → Missing → 예시 상품, 그리고 연구 기록. 추천 엔진은 실제 옷장만 쓰고 결과가 매번 같다. 날씨는 실제 데이터다. **미구현:** 실제 상품·구매 링크, 옷장 검색·필터, 앱 안 설문·피드백 |
| **배포·검증 수준** | 공개 사이트 접속·화면 표시·날씨는 **[배포] 확인**. 로그인 이후 흐름은 **[로컬]에서만** 확인했다(실제 Research DB에서는 미확인). **Gemini가 없어 옷 등록부터 막혀 있고**, 그래서 옷장·코디·Missing은 배포 환경에서 끝까지 해 볼 수 없다. 실제 iPhone 검증은 0건 |
| **강점** | 흑백 미니멀 디자인이 화면 전체에서 일관된다. 추천 이유와 점수(6개 지표)를 보여준다. 오류 안내가 한국어로 원인별이다. iPhone 사진 처리(HEIC·24MP)가 안정적이다. 개인정보를 빼고 연구 기록을 남긴다. 비밀키 노출 0 |
| **가장 큰 부족** | 1) **배포 사이트에서 아이콘이 모두 □로 보인다**(아이콘 폰트 404, P0) 2) **Gemini 미연결**로 핵심 흐름 시작 불가 3) 상품이 모두 가짜(Partner Brand A~G) 4) 영어 속성값과 한국어 화면이 섞인다 5) 404·사이트맵이 Expo 기본 영어 화면 그대로 |
| **조사 준비 수준** | **약 70%.** 앱 코드 쪽 남은 P0는 아이콘 폰트 1건(작업 30분 내외). 나머지 P0는 외부 조건이다: Gemini 결제·연결, Research DB 서버 연결 확인, 처리방침 게시, 실기기 E2E, 상품 데이터 결정 |

## ⑦ 권장 작업 순서

```
[바로, 병렬]
  A: P0-01 아이콘 폰트 ── 재배포(P0-08) ──┐
  B: P0-03 Research DB E2E ───────────────┤
  PO: P0-02 Gemini 결제 → B 연결 ─────────┤
  PO: P0-06 상품 방침 결정 ───────────────┤
  B·PO: P0-05 처리방침 ───────────────────┤
                                          ▼
[P0-01·02·03 끝나면]  P0-04 실기기 전체 흐름(PO + A) → 결과로 버그 반영
                                          ▼
[P0-04와 병렬로 A가 할 P1(서로 독립)]
  P1-01 한국어 사전 · P1-02 404·사이트맵 · P1-03 옷장 메뉴 · P1-04 버튼 위계
  P1-05 인트로 · P1-06 대비 · P1-07 홈 설명 · P1-14 캐시   → 한 번에 재배포
                                          ▼
[조사 1주 전]  P0-07 진행 리허설(기록 내보내기 포함) → P1-09·10·11 반영 여부 결정
```

- **A가 바로 할 수 있는 P0:** P0-01, 승인 후 재배포. 나머지 P0는 결제·결정·B 검증이 먼저다.
- **병렬 가능:**
  - P0-01 ↔ P0-02·03·05·06 (서로 다른 사람·시스템)
  - P1-01~07은 화면이 겹치지 않아 동시에 진행하고 한 번에 배포
- **순서가 필요한 것:** P0-04는 P0-01·02·03 뒤. P1-09는 Gemini 연결(P0-02) 뒤. P1-13은 처리방침(P0-05) 뒤.
